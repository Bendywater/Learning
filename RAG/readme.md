# RAG 知识
RAG (Retrieval-Augmented Generation，检索增强生成) 是一种将强大的信息检索 (Information Retrieval, IR) 技术与生成式大语言模型 (LLM) 相结合的框架。

RAG 的核心思想是：在让 LLM 回答问题或生成文本之前，先从一个大规模的知识库（如数据库、文档集合）中检索出相关的上下文信息，然后将这些信息与原始问题一并提供给 LLM，从而“增强”其生成能力，使其能够产出更准确、更具时效性、更符合特定领域知识的回答。


## 为什么要用RAG
尽管 LLM 本身拥有海量的知识，但它依然面临三个核心挑战，而 RAG 正是解决这些挑战的有效方案：

1. 解决知识时效性问题（对抗“知识截止”）

预训练的 LLM 的知识被固化在其 训练数据的截止时间点（Knowledge Cutoff）。例如，GPT-4 的知识库可能截止于 2023 年 12 月。对于此后发生的新事件、新知识，LLM 无法直接给出准确答案。RAG 通过 动态检索外部知识源，为 LLM 提供“实时”的知识补充，从而克服了知识过时的问题。

2. 打通私有数据访问（赋能企业级应用）

出于数据安全和商业机密的考虑，企业内部的 私有数据（如产品文档、内部知识库、客户数据等）无法被公开的 LLM 直接访问。RAG 技术能够安全地连接这些私有数据源，在用户提问时，仅将与问题相关的片段信息提取出来提供给 LLM，使其能够在 不泄露全部数据 的前提下，基于企业自身的知识进行回答，实现真正可用的企业级智能应用。

3. 提升回答的准确性与可追溯性（对抗“模型幻觉”）

LLM 有时会产生 “幻觉（Hallucination）” ，即编造不符合事实的信息。RAG 通过提供明确的、有据可查的参考文本，强制 LLM 的回答 基于检索到的事实，大大降低了幻觉的发生率。同时，由于可以展示引用的原文，使得答案的 来源可追溯、可验证，增强了系统的可靠性和用户的信任度。

## RAG的流程
1. 文档加载和切分：通过文本分割器（Text Splitter）将文档拆分为较小的文本片段（Segments），严格适配嵌入模型和生成模型的上下文窗口限制（Context Window）。
2. 向量化：通过嵌入模型（如 OpenAI text-embedding-3 或 Hugging Face 上的开源模型）将文本片段映射为语义向量表示（Document Embedding，也就是高维稠密向量）。
3. 存入向量数据库：将生成的嵌入向量、原始内容及其对应的元数据存入向量存储库（如 Milvus, Faiss 或 pgvector）。
4. 查询向量化：使用嵌入模型（Embedding Model）将用户查询转换为语义向量表示（Query Embedding，也就是高维稠密向量），以捕捉查询的语义信息。
5. 相似度检索：在嵌入存储（Embedding Store）中，通过语义相似性搜索找到与查询向量最相关的文档片段（Relevant Segments）。
6. 生成增强：将检索到的相关片段和原始查询作为上下文输入给 LLM，并使用合适的提示词引导 LLM 基于检索到的信息回答问题。
7. 生成输出：用户输出自然语言回复，并附带相关的参考资料链接。

## 做一个RAG项目：科普内容审核统计

### 项目背景
科普短视频常见问题不是“内容是否违规”，而是“内容是否可信”。例如：

- 医疗健康类：“每天喝某种水可以治糖尿病”
- 食品安全类：“某食品添加剂一定致癌”
- 天文地理类：“今晚会出现千年一遇天象”
- 生活常识类：“某个偏方可以替代正规治疗”

这类审核不能只靠大模型直接判断，因为大模型可能会凭常识猜测，无法保证可追溯性。更合适的方式是使用 RAG：先检索权威资料，再让模型基于证据判断视频说法是否成立。

### 项目目标
输入一个科普短视频，系统输出审核结论：

1. 视频核心观点是什么。
2. 观点是否真实：`真实`、`虚假`、`部分真实`、`证据不足`。
3. 判断依据来自哪些权威资料。
4. 视频中哪些句子或画面存在风险。
5. 给审核人员一个可解释的审核报告。

### 核心难点
这个项目不是简单问答，而是“事实核查 + 证据归因”。需要解决几个问题：

1. 视频是多模态内容，需要先抽取文本信息。
2. 科普内容往往包含多个观点，需要拆成多个可验证的 claim。
3. 检索结果必须来自可信来源，不能随便抓网页。
4. 模型输出必须引用证据，不能凭空判断。
5. 有些内容不是非真即假，而是“条件不完整”“夸大结论”“偷换概念”。

### 整体流程

```text
短视频
  ↓
语音识别 ASR：提取视频口播字幕
  ↓
OCR：提取画面文字、标题、贴纸、图表文字
  ↓
关键帧理解：提取画面中的物体、场景、实验过程
  ↓
内容清洗与合并：得到完整的视频文本
  ↓
Claim 抽取：拆成多个待核查观点
  ↓
RAG 检索：从权威知识库检索证据
  ↓
LLM 判断：基于证据判断真假
  ↓
审核报告：结论、证据、风险句、置信度
```

### 知识库设计
科普审核的知识库应该优先使用权威、稳定、可追溯的数据源。

可以按领域建设多个知识库：

| 领域 | 推荐资料来源 | 适合审核的问题 |
| --- | --- | --- |
| 医疗健康 | 卫健委、WHO、CDC、医学指南、药品说明书 | 疾病、治疗、疫苗、药品、偏方 |
| 食品安全 | 国家市场监管总局、食品安全标准、EFSA、FDA | 添加剂、保健品、致癌风险、食品谣言 |
| 天文地理 | NASA、中科院、气象局、地震局 | 天象、气候、地震、灾害 |
| 科学常识 | 科普中国、百科条目、教材、论文综述 | 物理、化学、生物、生活常识 |

每条知识片段建议保存以下元数据：

```json
{
  "doc_id": "source_001",
  "title": "资料标题",
  "source": "资料来源",
  "url": "原文链接",
  "domain": "medical",
  "publish_date": "2025-01-01",
  "authority_level": "official",
  "chunk_text": "切分后的正文片段"
}
```

### 数据处理模块

#### 1. 视频文本抽取
需要从视频中抽取三类信息：

- `asr_text`：语音识别得到的口播内容。
- `ocr_text`：画面文字，例如标题、字幕、实验标签。
- `visual_summary`：关键帧画面描述，例如“画面展示一瓶保健品和血糖仪”。

最终合并成统一输入：

```json
{
  "video_id": "video_001",
  "title": "三天降低血糖的方法",
  "asr_text": "这个方法不用吃药，三天就能让血糖恢复正常...",
  "ocr_text": "天然降糖 无副作用",
  "visual_summary": "视频多次展示保健品瓶身和血糖仪读数"
}
```

#### 2. Claim 抽取
不要直接审核整段视频，而是先拆成多个可验证观点：

```json
[
  {
    "claim_id": "c1",
    "claim": "某种保健品可以在三天内让血糖恢复正常",
    "claim_type": "medical",
    "risk_level": "high"
  },
  {
    "claim_id": "c2",
    "claim": "这个方法可以替代药物治疗",
    "claim_type": "medical",
    "risk_level": "high"
  }
]
```

### RAG 检索策略
建议不要只做一次向量检索，审核场景更适合混合检索：

1. 向量检索：召回语义相近的资料。
2. 关键词检索：召回疾病名、药品名、机构名、标准编号等精确内容。
3. Rerank：对召回结果重新排序，优先选择权威来源。
4. 证据过滤：过滤低质量、来源不明、营销类内容。

检索结果可以组织成：

```json
{
  "claim_id": "c1",
  "evidence": [
    {
      "source": "WHO",
      "title": "Diabetes fact sheet",
      "url": "https://...",
      "text": "糖尿病治疗需要基于饮食、运动、药物和医学监测..."
    }
  ]
}
```

### 判断逻辑
LLM 的任务不是自由发挥，而是基于证据做分类。

建议使用以下标签：

| 标签 | 含义 |
| --- | --- |
| `true` | 证据支持视频观点 |
| `false` | 权威证据明确反驳视频观点 |
| `partially_true` | 部分成立，但视频存在夸大、遗漏条件或误导 |
| `not_enough_evidence` | 检索证据不足，不能下结论 |

输出示例：

```json
{
  "video_id": "video_001",
  "overall_label": "false",
  "risk_level": "high",
  "claims": [
    {
      "claim": "某种保健品可以在三天内让血糖恢复正常",
      "label": "false",
      "reason": "检索到的权威资料不支持保健品可以快速治疗糖尿病，且糖尿病治疗需要医学监测和规范治疗。",
      "evidence_ids": ["e1", "e2"],
      "confidence": 0.86
    }
  ],
  "review_summary": "该视频宣称保健品可以快速替代正规治疗，属于高风险虚假健康科普内容。"
}
```

### Prompt 设计

审核判断 Prompt 可以这样设计：

```text
你是一个科普内容事实核查助手。请只基于给定证据判断视频观点是否可信。

要求：
1. 不允许使用证据之外的知识直接下结论。
2. 如果证据不足，输出 not_enough_evidence。
3. 如果视频观点存在夸大、遗漏条件、偷换概念，输出 partially_true。
4. 每个判断必须引用 evidence_id。
5. 输出 JSON，不要输出额外解释。

待核查观点：
{claim}

检索证据：
{evidence}

输出字段：
label, reason, evidence_ids, confidence
```

### 技术选型建议

MVP 阶段可以选择简单稳定的方案：

| 模块 | 可选方案 |
| --- | --- |
| ASR | Whisper / faster-whisper |
| OCR | PaddleOCR |
| 文档切分 | LangChain / LlamaIndex / 自定义切分 |
| Embedding | bge-m3 / text-embedding-3-large / m3e |
| 向量库 | FAISS / Milvus / pgvector |
| 关键词检索 | Elasticsearch / OpenSearch / BM25 |
| Rerank | bge-reranker / Cohere Rerank |
| LLM | Qwen / DeepSeek / GPT 系列 |
| 服务接口 | FastAPI |
| 前端演示 | Streamlit / Gradio |

### MVP 功能范围
第一版不要做太大，建议先完成这 5 个能力：

1. 上传一个短视频或输入一段视频文案。
2. 自动抽取 3 到 5 个核心 claim。
3. 对每个 claim 检索 5 条以内权威证据。
4. 输出真假判断和引用依据。
5. 生成审核报告 JSON 和可读文本。

### 评估指标
审核项目需要同时评估检索和判断效果：

| 指标 | 说明 |
| --- | --- |
| Claim 抽取准确率 | 是否抽到了视频真正表达的核心观点 |
| Evidence Recall | 正确证据是否被检索出来 |
| 判断准确率 | true / false / partially_true / not_enough_evidence 分类是否正确 |
| 引用准确率 | 模型引用的证据是否真的支持判断 |
| 幻觉率 | 输出是否出现证据中没有的信息 |
| 人审节省时间 | 相比人工审核是否减少判断时间 |

### 推荐实现顺序

1. 先做文本版：输入视频标题和口播文案，输出审核结果。
2. 再接入知识库：整理 50 到 200 篇权威资料，建立 FAISS 索引。
3. 加入 Claim 抽取：把长文案拆成多个待核查观点。
4. 加入证据引用：每个结论都必须绑定 evidence_id。
5. 最后再接视频能力：ASR、OCR、关键帧理解。

输入：


输出：

```json
{

```
